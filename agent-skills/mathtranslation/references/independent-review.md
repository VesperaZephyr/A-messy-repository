# 翻译与审阅的上下文隔离

长篇翻译、整章审校或用户要求独立复核时使用。单个句子的修订不必启动整套流程。
这是一种任务分工与证据隔离方法，不是模型训练，也不能保证审阅者完全无偏。

## 主持者负责边界，不替审阅者预判答案

主持者准备只含必要事实的交接包：原书版本与文件哈希、物理页范围及印刷页映射、
本单元前后各一段必要上下文、项目术语表及版本、宏接口、编号/引用约定、允许写入路径、
交付路径、构建命令。跨节定理依赖要明确附上，不能为了隔离而删去必要假设。
审阅包另附冻结译稿快照及哈希，不附翻译者的推理、信心、自评或预期结论。
实际交接分两阶段：先只发原书与约定，收到落盘的原书清单后，再发冻结译稿。
不要提前发送译稿路径或译者边表，让“先看原书”成为可检查的交接顺序。
尚待裁定的术语在术语表中标明，避免把翻译者的猜测变成审校前提。

使用当前环境提供的子智能体接口；若支持 `fork_turns="none"`，显式使用它。
默认继承完整对话的子智能体不满足这里的独立审阅条件。接口不支持干净上下文时，
采用独立会话或说明只能做分轮自审，不冒称独立审阅。不要擅自新建用户侧聊天。

| 角色 | 输入与职责 | 写入权限 |
|---|---|---|
| 翻译者 | 原书、必要依赖、术语与模板；交付译稿及未决问题 | 独占该单元草稿目录 |
| 审阅者 | 原书与冻结译稿；先做原书清单，再逐项对照 | 只写自己的审阅报告 |
| 图形专项审阅者（按需） | 原书图、候选 TikZ/资产、最终页；独立列节点/边或几何事实 | 只写专项报告 |
| 主持者 | 合并、裁定分歧、更新全局术语/标签、整书构建 | 正式项目与全局文件 |

共享文件系统不等于共享写入权。禁止多人同时修改 main.tex、术语表、同一章节或同一构建目录。
并行翻译不同单元时分配互斥路径；编译使用各自临时目录，或由主持者串行执行。
短任务可顺序启动翻译者与审阅者，避免为凑角色增加无效并行。

## 可直接改填的任务包

翻译者：

```text
翻译单元 <unit-id>。只读取 <原书路径、物理页范围>、<必要上下文/术语/宏约定>。
写入范围为 <独占目录>；不要修改正式章节或全局文件。
交付中文 TeX、原书内容到译稿位置的对应表，以及无法从原书确认的问题。
保留量词、假设、编号、脚注、全部图和练习；不要自行补证明或修正原书。
```

审阅者第一阶段（新上下文，不转发上一角色的对话）：

```text
为 <unit-id> 独立建立原书内容清单。原书为 <路径、版本、物理页范围>。
术语与接口约定为 <路径>。只看原书，记录段落/陈述/公式/脚注/习题/图，
将清单保存至 <独占清单路径> 并返回；尚不读取任何译稿。
```

主持者收到清单后，再向该审阅者发送第二阶段：

```text
现在对照已保存的原书清单审阅 <unit-id>，译稿快照为 <路径、哈希>。
报告写入 <独占报告路径>，不要修改译稿。
逐项报告遗漏、增译、数学含义变化及图形问题，附原书页/区域、译稿位置、证据和建议。
分别报告已核查范围与未决范围；不以语句流畅、数量相等或编译成功认证保真。
```

## 修复与验收

1. 审阅发现使用稳定 ID：`unit/type/sequence`；至少含原书页/区域、译稿文件/行、
   严重程度、具体差异、证据、建议与状态。单元对应表记录无缺陷的内容以证明覆盖。
2. 主持者先裁定源版本/术语分歧，再把具体问题交给翻译者修复；审阅者的首轮报告留存。
   不能用“多数代理同意”替代原书证据，不能因审阅者没有报告就补写“全部通过”。
3. 修复后冻结新快照。复核者检查每项修复及受影响的相邻句、公式、编号和引用；
   原审阅者可做回归检查，重大争议再交新的干净上下文审阅者。
4. 主持者在正式项目重编译，核对实际 PDF 页与交叉引用。源码审阅通过不自动覆盖最终排版。
   修改了已核查单元或依赖的宏/术语/资产后，相关结论标为待复核。
5. 按 `待译 → 已译 → 已独立审阅 → 已修复 → 已复核 → 最终 PDF 已验证` 记录状态；
   无工具、无视觉或缺原书的限制单独记录。每轮必须有具体缺陷、修复或证据进展；
   连续两轮无法推进的争议保留为未决，继续不受影响的工作，不无限互相改稿。
